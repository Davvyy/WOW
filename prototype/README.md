# 챌로리 프로토타입

설계 문서 `docs/06-화면-설계.md`를 그대로 화면으로 옮긴 클릭 프로토타입입니다. 빌드 없이 파일을 브라우저로 열면 됩니다(폰트·아이콘만 Google Fonts에서 받음).

| 파일 | 내용 |
|---|---|
| `index.html` | 참가자 앱 P1~P12. 390×844 폰 프레임 + 검수 패널(화면·상태 변형·테마·글자 120%) |
| `console.html` | 운영자 웹 콘솔 OP1~OP4 (1280px 기준, 1024px까지) |
| `data.js` | 단일 데이터 소스 + 점수 엔진. 두 HTML이 함께 읽음 |

## 해시 라우팅

`#화면id-변형` 형식. 변형을 생략하면 기본 상태.

- 참가자: `#p1`, `#p1-valid`, `#p2-record-mode`, `#p4-zero`, `#p5`, `#p5-review`, `#p5-substitute`, `#p5-published`, `#p6-push-ask`, `#p7`, `#p7-auto`, `#p7-downward`, `#p7-snack`, `#p8-watch`, `#p8-ios`, `#p9-cumulative`, `#p9-report`, `#p10-review`, `#p10-verdict-void`, `#p11`, `#p12-delete` …
- 운영자: `#op1`, `#op1-locked`, `#op2-drawer`, `#op3-dry-run`, `#op3-sla-critical`, `#op4-blocked`, `#op4-published`, `#op4-archived` …

전체 변형 목록은 각 파일의 검수 패널(또는 `SCREENS` 정의)에서 볼 수 있습니다.

## 실제로 동작하는 것

- P7 식사 편집: 후보 칩(이름과 kcal 동시 변경), 반 공기/1공기/곱빼기, 국물 −40%, 개수 스테퍼, 먹은 것만 체크 → 합계 즉시 재계산
- P11 시뮬레이터: 걸음·달리기·섭취 입력 → `ENGINE.simulate`로 점수 재계산(P5·P10과 같은 함수)
- P9 응원 하트(1일 1회), 세그먼트 전환, 신고 시트
- OP3 판정 폼: 판정 선택 → 점수 영향 미리보기(dry-run) → 당사자 알림 문구 조합

## 예시 데이터 (단일 소스)

- 챌린지: 가을 걷기 챌린지, 10.6~11.2(28일), 42/60명, 오늘 10.13(D+8)
- 지수(나): 남 · 1996 · 175 cm · 70 kg → BMR 1,648.75 → 1,650 · 대체값 742.5 · 하한 1,320
- 오늘: 걸음 9,000(삼성헬스) → 활동 294 · 섭취 1,800(420/780/600) → 순적자 144 → **28.8점** · 누적(확정분) **312.6점**
- 워치 예시(밤산책): 여 58 kg · 달리기 30분 9 km/h → 활동 420.5 · 섭취 1,350 → **72.1점**
- 정정 예시(10.12): 저녁 600 무효 → 대체값 742.5 → 41.2 → 12.7점

모든 숫자는 `data.js`의 산식 함수로 계산되며, 문서 `docs/04` §6 예시와 같은 입력을 씁니다.

## 검수 팁

- 검수 패널의 테마 토글로 라이트/다크/시스템 전환, 글자 120%로 큰 글씨 확인
- Playwright 스크린샷: 각 화면은 `window.showScreen('p5-review')`로 전환 가능
