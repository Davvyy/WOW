# 01. 유사 앱 조사 보고서 — 다이어트 챌린지 앱 설계를 위한 시장·기술 조사

작성일: 2026-09-30 | 상태: 조사 단계 최종본 | 다음 단계: 02-기능정의, 03-UI/UX 설계

## 1. 요약 (Executive Summary)

- **순칼로리 표시 방식은 사실상 표준화**되어 있다. MyFitnessPal·Yazio·Lifesum·Cronometer·Lose It! 모두 첫 화면 히어로가 "목표 − 섭취 + 운동 = 남음" 또는 Eaten/Burned/Remaining 링이다. 우리 홈도 이 문법을 따르되, Apple Activity 링을 재현하면 HIG 위반이므로 독자적 단일 링으로 그린다.
- **운동 칼로리를 예산에 되돌리는 비율은 앱마다 100%(MFP·Yazio·Lifesum) / 50%(Noom) / 기준 활동량 초과분만(Lose It!·Cronometer) / 0%(MacroFactor)로 갈린다.** 순위 공정성을 위해 우리는 활동 칼로리 상한과 인정 비율을 규칙으로 명문화해 화면에 노출한다.
- **음식 사진 AI는 편의 기능이지 정밀 도구가 아니다.** NIH 대사 주방 연구(2026)에서 MFP·Lose It!·Cal AI 등 4개 앱이 끼니당 평균 250~345 kcal(약 33%) 과소 추정했고, 전용 데이터셋(Nutrition5k)에서도 단일 사진 kcal 오차는 ±26% 수준이다. 동아시아 음식은 서양식보다 더 나쁘다. AI 결과는 반드시 "편집 가능한 초안"이며, 순위에는 사용자 확정값만 반영해야 한다.
- **한식 인식 엔진 후보는 멀티모달 LLM(Gemini 2.5 Flash·Claude Haiku 4.5, 장당 0.3~3.5원) + 식약처 영양 DB 매핑**이 MVP 1순위, 두잉랩 FoodLens(국내, 가격 비공개·영업 문의)가 2순위다. LogMeal·Passio·Calorie Mama는 한식 근거·가격이 확인되지 않아 보류.
- **소비 칼로리 데이터는 벤더 클라우드 API가 아니라 OS 허브(iOS HealthKit, Android Health Connect)에서 읽는다.** Google Fit API 종료, Fitbit API → Google Health API 전환, Strava API 유료화, Garmin Health API 신규 승인 중단이 겹쳐 벤더 API는 v1에서 제외한다.
- **Galaxy 폰 단독 사용자(국내 다수)는 삼성헬스→Health Connect로 걸음·거리·운동 세션은 오지만 일일 활동 칼로리·층수는 오지 않는다.** 따라서 순위용 소비 칼로리는 플랫폼 값이 아니라 **자체 MET 엔진(걸음·거리·시간·체중 기반)**으로 모든 참가자에게 동일 공식을 적용해야 한다.
- **"순칼로리 최소 = 1등" 규칙은 식사 미기록과 굶기를 보상한다.** 순위 지표는 "개인 목표 대비 순적자 달성률(%)" + 기록 성실도 가중 + 섭취 하한 클램프로 정의한다(Apple 링의 목표 대비 % 구조, Noom·MFP의 최소 섭취 하한, HealthyWage의 2%/주 규칙 참조).
- **국내 챌린지 UX 문법**: 챌린저스(예치금 85%/100% 환급·인증샷·상호 신고·레드카드), 캐시워크(팀원 확인 필수 챌린지·일일 상한), 삼성헬스 투게더(실시간 순위·배지·메시지 보드), 손목닥터9988/워크온(포인트·지역화폐)이 표준이다. 판정 기준 모호·검토 지연·지급 지연이 최대 CS 리스크였다.
- **부정행위는 기술+규칙으로 함께 막는다.** 수동 입력 배제(Health Connect recordingMethod, HealthKit WasUserEntered), 인앱 카메라 전용·서버 시각·해시 중복 검사, Play Integrity/App Attest, 생리적 상한과 "검토 중" 상태를 기본 설계에 넣는다.
- **핵심 기록 기능(사진·바코드·검색)은 무료·무광고로.** MFP는 2026-05 유료화 확대 후 iOS 평점이 4.6→4.2로 급락했다. 챌린지 앱은 참가자 무료·운영자(B2B) 과금이 적합하다.

## 2. 조사 범위와 방법

- **범위**: 13개 관점 — 글로벌 식단앱 8종, AI 음식사진 앱 13종, 국내 앱 12종, 활동 측정 플랫폼/웨어러블 8종, 챌린지·리더보드 메커니즘 11종, 기술 구현(칼로리 공식·센서 API·음식 인식 API·한식 DB·크로스플랫폼), UX/UI 패턴, 공정성·프라이버시·규제, 순위 산식, 운영자 콘솔, 한식 인식 엔진 실비교, Galaxy 폰 단독 데이터 경로, 체중 검증.
- **방법**: 관점별 WebSearch 36~46회와 WebFetch. 단, 세션 네트워크 프록시가 앱스토어·플레이스토어·공식 헬프센터·국내 언론·학술 DB 대부분을 차단해, (1) Apple/Android 개발자 문서, (2) GitHub 공개 저장소(오픈소스 코드·이슈 트래커·리뷰 데이터셋·경쟁사 분석 문서), (3) 검색 엔진 요약을 1차 근거로 삼았다.
- **표기 원칙**: 원문을 직접 확인하지 못한 항목은 **"확인 못함"**, 2차 출처는 **[2차]**, 원자료 간 수치가 다르면 **"상충"**으로 병기했다. 자사 SEO 블로그(nutrola, nutriscan 등)와 출처 불명 벤치마크(ai-food-tracker.com, PlateLens ±1.1%)는 신뢰도 낮음으로 표시하고 설계 근거로 쓰지 않았다.
- **수치 기준 시점**: 가격·평점은 2025~2026년 리뷰 매체 인용값이며 스토어 지역·시점에 따라 달라진다.

## 4. 카테고리별 심층 분석

### 4.1 글로벌 식단앱
- 예산 산정은 Mifflin-St Jeor(MFP·Yazio·Cronometer) 또는 Harris-Benedict(Lifesum·Noom)에 활동계수를 곱하고 감량 목표를 빼는 구조다. Yazio는 PAL 값(1.25/1.38/1.52/1.65)을, Noom은 50%·0.05kcal/보 규칙을 공개해 투명성이 높다.
- **이중계산이 가장 흔한 기술 함정**이다. 트래커의 총 소모에 BMR이 포함되고 앱 활동계수에도 일상활동이 들어 있어 Yazio·Cronometer·MFP 모두 "활동레벨을 낮게 잡아라"고 안내한다. 순위 앱은 BMR(고정)+센서 기반 순 활동 칼로리 구조로 처음부터 분리해야 한다.
- 최소 섭취 하한은 관례다(MFP 1,200/1,500, Noom 1,320/1,540 kcal). Noom은 단일 목표 대신 "범위(Zone)"를 준다.
- 챌린지/순위는 의외로 빈약하다. Lose It!과 FatSecret만 챌린지가 있고 순위형 리더보드를 전면에 세운 앱은 없다. 리텐션은 스트릭·다이아몬드·배지(Yazio), Life Score(Lifesum), 코치·그룹(Noom)으로 만든다. MFP는 저사용 뉴스피드를 폐지했다.
- 페이월 이동은 평점 급락으로 직결된다(MFP 2026-05 4.6→4.2). 바코드·사진 로깅은 사용자가 "기본"으로 기대하는 기능이 됐다.

### 4.4 활동 측정 플랫폼/웨어러블
- **벤더 API는 2025~2026년에 폐쇄·유료화됐다.** Google Fit API는 2024-05 신규 가입 종료, 지원 종료 시점은 2025-06-30(관점 1)과 "2026년 말"(Google 공식 FAQ, 관점 4) 두 값이 상충하나 신규 설계에 쓸 수 없다는 결론은 같다. Fitbit Web API는 2026-10-30 종료 예정(연장 보도, 확인 필요)·Google Health API(CASA 보안평가 필요)로 대체, Strava는 2026-06부터 API 사용에 유료 구독 의무·타인 데이터 표시 금지, Garmin Health API는 법인 전용·신규 접수 중단 보고. Garmin·Fitbit·Xiaomi·Zepp·Strava 앱은 모두 HealthKit/Health Connect에 "쓰기"하므로 허브 2개만 연동하면 대부분의 워치가 커버된다.
- **iPhone 단독**: 걸음·거리·층수(기압계 모델)는 자동 기록, iOS 16+는 워치 없이도 `activeEnergyBurned`를 iPhone이 계산(Apple 엔지니어 포럼 답변; 공식 문서는 "Apple Watch에서 자동 기록"만 명시 — 상충, 실기기 확인 필요). 기초대사 기록 여부 확인 못함. iOS 17+는 `HKWorkoutSession`을 iPhone에서 실행 가능.
- **Galaxy 폰 단독**: Android 14+SDK ext 20 이상은 Health Connect가 폰 걸음을 자체 기록(1분 배치, READ_STEPS 앱 존재 시). 삼성헬스→Health Connect로 걸음·거리·심박(워치)·수면·운동 세션(+세션 칼로리)은 넘어오지만 **일일 활동 칼로리·all-day 활동시간·안정심박·HRV는 오지 않고 층수는 증거 없음**(오픈소스 이슈 다수). Samsung Health Data SDK에는 ACTIVITY_SUMMARY·FLOORS_CLIMBED가 있지만 파트너 승인이 사실상 닫혀 있어 로드맵에서 제외한다.
- **폰 vs 워치 형평성**: 자유생활 3일 검증에서 iPhone 27%·손목 트래커 22~23% 걸음 과소집계, 느린 보행에서 MAPE 40%. 칼로리는 더 나빠 Stanford 2017에서 최고 기기도 27%, Apple Watch 약 40% 오차, 2025 메타분석 약 28%. "한 사람 안의 폰+워치 중복"은 허브가 병합(iOS `HKStatisticsCollectionQuery`, Android `aggregate()` 우선순위)해 주지만 **참가자 간 기기 차이는 아무도 해결해 주지 않는다.** 원시 샘플 합산 시 27% 과다 또는 1만 보 누락 사고 사례가 있다.
- 동기화 제약: iOS 백그라운드 전달은 stepCount 기준 최대 1시간 1회, Health Connect는 포그라운드 기본·백그라운드 별도 권한·30일 이력 제한·Changes 토큰 30일 만료. 워치는 다음날 아침 동기화되거나 삼성헬스가 칼로리를 사후 수정하므로 "실시간 순위"는 불가능하고 잠정/확정 분리가 필요하다.

### 4.5 챌린지·리더보드 메커니즘
- **순위 지표 유형**: 개인 달성률(챌린저스, StepBet 개인화 목표), 감량%(DietBet 4%/4주, HealthyWage 10%), 절대 걸음(Fitbit·Garmin·삼성), 목표 대비 %(Apple 링 %당 1점·일 600점 [2차]), 심박 존 가중(Strava Relative Effort, GoldenCheetah TRIMP), 빈도(Strava Local Legend), 팀 1인당 평균(YuMuuv CPL 2026).
- **학술 근거**(2차 인용): 경쟁>지지>협력(Patel 2019 +920보/일), 팀 전용 보상은 실패·개인+팀 혼합이 최선(Patel 2016: 18/17/25/35%), 달성자끼리만 분배하는 그룹 풀이 개인 보상보다 약 3배 감량(Kullgren 2013), 손실 프레임 45% vs 30%, 예치금 요구는 가입률 62%→38%로 감소, 게이미피케이션 효과는 14주에 g 0.42→0.15로 감쇠, 노력은 1등과 꼴찌에서 최대·중간에서 최소(U자, Gill 2019), 깨진 스트릭 강조는 이탈 유발(Silverman & Barasch 2023).
- **칼로리 랭킹의 함정**: 자기보고 섭취는 DLW 대비 10~25% 과소, 순칼로리 순위는 사진을 덜 올리는 사람이 이긴다. 칼로리 트래킹과 섭식장애 연관(Levinson 2017: ED 환자 73%가 앱이 기여했다고 인식), 공개 순위와 ED 증상 상관 r=0.36. 소비 칼로리는 체중×MET×시간이라 무거운 사람이 유리. 한 설계 문서는 "칼로리는 절대 순위화하지 않는다"를 규칙으로 못 박았다.
- **완화 장치 카탈로그**: 자기 목표 대비 %+일일 상한(Apple, Whoop), 감량 속도 상한·초과분 무효(HealthyWage 2%/주, 팀 합산 16.59% 캡, DietBet 12% 실격·BMI 18.5 하한), 수동 입력 배제(Strava), 인증 단어·연속 영상·심판(DietBet), 완주형·협동 누적형 옵션(Strava Group Goal), 신규 계정 순위 제외·48시간 이후 소급 금지·동점은 공동 순위.
- 챌린지 생명주기 공통점: 기준선 측정 단계(워밍업 주·시작 인증)가 본 챌린지와 분리, 초대는 상호 승인, 정산 시점의 검증 창이 별도. 운영자 콘솔은 PRD 사례 기준 대시보드·챌린지·참가자·검수 큐(반려 사유 템플릿·SLA 72h·확정 후 잠금)·공지·정산·리포트 IA, 챌린지 상태 9종, 판정 4단계(승인/경고/무효/레드카드), 팀 순위 기본 "1인당 평균".

## 5. 기술 조사 결과

### 5.1 운동 소비 칼로리 계산식
- 기본식: **kcal(gross) = MET × 체중(kg) × 시간(h)**, 순 활동 칼로리 **net = (MET − 1) × kg × h**. 1 MET = 3.5 mL O₂/kg/min ≈ 1 kcal/kg/h, kcal/min = VO₂ × kg / 200. 순위에 BMR과 활동을 분리하려면 net 값을 쓴다. 기준 데이터는 2024 Adult Compendium(Herrmann et al., J Sport Health Sci 2024;13:6–12)이며 activity_code를 데이터 모델에 저장한다.
- ACSM 대사 방정식: 걷기(S<134 m/min) VO₂ = 0.1·S + 1.8·S·G + 3.5, 달리기 VO₂ = 0.2·S + 0.9·S·G + 3.5 (S m/min, G 경사 소수). 스테핑 식은 원문 확인 못함.
- 걸음→칼로리: 케이던스 약 100 steps/min ≈ 3 MET(Tudor-Locke 2018). 70 kg·3.8 MET·100 spm → 약 0.044 kcal/걸음(1만 보 ≈ gross 440 / net 320 kcal). Noom은 1보 0.05 kcal 단순식.
- BMR: Mifflin-St Jeor 남 10W+6.25H−5A+5, 여 −161; 개정 Harris-Benedict 남 88.362+13.397W+4.799H−5.677A; Schofield(WHO) 식은 openScale이 500~5,000 kcal/day로 클램프. PAL(1.2~1.9)로 TDEE를 만든 뒤 센서 활동 칼로리를 더하면 이중계산.

- 집계 규칙: iOS는 `HKStatisticsCollectionQuery(.cumulativeSum, 1일)`만 사용(HKSampleQuery 합산 금지), Android는 `aggregateGroupByPeriod(Period.ofDays(1))`(readRecords 합산 금지).
- 권한·심사: iOS `NSHealthShareUsageDescription`·`NSMotionUsageDescription`(없으면 크래시)·HealthKit background-delivery entitlement(iOS 15+), 읽기 거부를 앱이 알 수 없음. Android `android.permission.health.READ_*`, `READ_HEALTH_DATA_IN_BACKGROUND`, `READ_HEALTH_DATA_HISTORY`(30일 이전), `ACTIVITY_RECOGNITION`(API 29+), rationale 액티비티, Play Console Health apps 선언 폼(허용 카테고리에 "Corporate Wellness & Rewards" 포함 vs "Rewards 없음" — 관점 간 상충, 재확인 필요). - 백그라운드 폴백: Android Recording API(`LocalRecordingClient`, 계정 불필요, 걸음·거리·칼로리 10일 보관), 포그라운드 서비스 `health` 타입(API 34).

## 6. 공정성·부정행위·건강리스크·프라이버시

- **부정행위 유형**: 폰 흔들기·스윙 장치·반려동물 부착, 걸음 생성 앱·수동 입력, 루팅·모의 센서·에뮬레이터·API 직접 호출, 다중 계정·기기, 옛 사진·타인 사진·빈 접시·사진 재사용·EXIF 위조, 그리고 **가장 저렴한 부정인 식사 미기록**.

## 7. 사용자 불만에서 배우는 "하지 말아야 할 것"

1. **핵심 기록 기능 유료화** — MFP 바코드·사진 유료화 후 평점 급락, Lose It! 가격 인상 논란, Garmin Connect+ 배지 페이월 보이콧.

## 8. 우리 앱을 위한 설계 시사점 (Design Implications)

1. **홈 히어로 = 오늘의 순칼로리 단일 링.** 링 안에 순적자/목표, 아래 섭취·소비 숫자와 오늘 순위·변동을 한 카드로. Apple 3중 링 재현 금지, 게이지에 현재값·0·목표 텍스트 병기. [MFP·Yazio·Lifesum·Cronometer 홈, HIG Activity rings/Gauges]
2. **순위 기본 산식 = 개인 목표 대비 순적자 달성률.** D_d = (BMR_p + min(A_d, C_p)) − max(I_d, F_p), R_d = D_d/T_p, S_d = 100·clamp(R_d,0,1.5)·w_d. 기본값 T_p 500, C_p 2·T_p, F_p max(1,200, 0.8·BMR)은 "운영자 설정"으로 표기. [Apple 링 목표 대비 %, Noom·MFP 하한, HealthyWage 2% 규칙, TRIMP(100)]
3. **기록 성실도 가중 w_d**(식사 ≥2끼+활동 동기화 1.0 / 한쪽 0.5 / 없음 0)를 "오늘 반영률" 배지로 노출, 미기록일은 결측(0점). [자기보고 과소 10~25%, Prana "칼로리 순위화 금지"]
4. **운영자 순위 옵션**: 기본(달성률) / 절대 순칼로리 / 활동칼로리만(kcal/kg 토글) / 걸음(상한 30,000). 심박 존 가중은 워치 보유자 별도 리그. 팀전은 "1인당 평균" 기본, 개인 점수 독립 노출, 팀 보상은 자기 목표 달성자에게만. [GoldenCheetah W/kg, YuMuuv CPL 2026, Patel 2016·Kullgren 2013]
5. **소비 칼로리는 자체 MET 엔진으로 통일**: BMR + 걸음·거리·케이던스 기반 net 활동 kcal(2024 Compendium 코드 저장) + 운동 세션 kcal(중복 구간 제외) + 층수 보너스(상한). 플랫폼 활동 칼로리는 참고값. [삼성헬스 일일 활동 칼로리 HC 미전달, iPhone 단독 activeEnergy 상충, 워치 오차 ±30%]
