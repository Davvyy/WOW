## 프로토타입

- 참가자 앱: [`prototype/index.html`](../prototype/index.html) — 브라우저에서 바로 열면 됨. 해시로 화면·상태 변형 직접 이동(`#p5`, `#p5-review`, `#p7-auto` …).
- 운영자 웹 콘솔: [`prototype/console.html`](../prototype/console.html) — `#op1` ~ `#op4-archived`.
- 단일 데이터·산식: [`prototype/data.js`](../prototype/data.js) — 두 프로토타입이 같은 엔진으로 숫자를 계산한다(BMR·대체값·하한·점수 하드코딩 없음).

## 핵심 결정 요약

- 순위 지표: `S_d = 100 × clamp(((BMR + min(A, 1000)) − max(I, max(1200, 0.8·BMR))) / 500, 0, 1.5)`. 미기록 끼니는 대체값 `max(700, 0.45·BMR)`, 150 kcal 미만은 간식(섭취 합산, 슬롯 미충족), 확정 끼니 0개는 0점. 매시간 잠정, D+1 09:00 확정.
- 소비 칼로리: HealthKit / Health Connect 집계만 읽고, 순위용 값은 자체 MET 엔진(걸음 MET 3.8 고정, 자동 기록 세션, 층수 보너스 50층 상한)으로 전원 동일 공식.
- 섭취 칼로리: 인앱 카메라 전용 → 멀티모달 LLM(JSON) → 식약처 음식 표준데이터 1인분 × 배수 → 사용자 확정값만 순위 반영.
- 공정성·안전: 자동 기록만 인정, 상한·하한 클램프, 자동 플래그 5종 → 검토 중(타인에게는 "집계 중") → 소명 1회(72h) → 승인/경고/무효/순위 제외. 기록 모드(만 19세 미만·BMI<18.5·임신/수유·섭식장애 병력), 수치심 없는 카피.
- 기술: Flutter + `health` 패키지, Supabase(Postgres·Auth·Storage·Edge Functions·pg_cron), Gemini 2.5 Flash(+Claude Haiku 어댑터), 운영자 콘솔은 웹.
