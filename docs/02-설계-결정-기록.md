## 3. MVP 범위 확정

**확정(1회차: 30~100명, 7~30일, 개인전, 무상금)**
1. Kakao/Apple 로그인, 6자리 초대코드. 초대 링크 = 웹 랜딩(코드·스토어 버튼) + 설치자는 Universal Links/App Links로 코드 자동 입력, 미설치자는 랜딩에서 코드 복사 → 설치 후 첫 실행 P1에서 클립보드 코드 감지로 입력 제안(유료 deferred deep link는 v1.1, 미결 10)
2. 필수 4항목(성별·생년·키·체중) → 즉시 BMR·목표 표시, 만 14세 미만 차단, 만 19세 미만(민법 성년 미만)·BMI<18.5·임신/수유·섭식장애 병력 → 기록 모드(순위 제외, 사유 비공개)
3. 동의 3분리: 약관(필수) / 건강 민감정보(필수) / 음식 사진 국외 AI 전송(**선택**, 미동의 시 검색 경로, 자격 불이익 없음)
4. HealthKit/Health Connect 읽기 연결(교육 카드 뒤 기능 시점 요청), 일별 집계 쿼리만, 수동 입력 제외, 3일 재조회
5. 자체 MET 엔진: BMR + 걸음(고정 MET 3.8) + 자동 기록 달리기·계단 세션 + 층수 보너스(50층 상한). 세션·층수는 **MVP 필수**(요구 1)
6. 식사: 인앱 카메라 전용 → 3초 내 홈 복귀 → Gemini 2.5 Flash JSON → 식약처 DB kcal → 분석 완료 푸시 → 편집·확정(확정값만 순위)
7. 편집 UI: 항목+가정 분량, top-3 후보 칩(이름 변경 시 kcal 재계산), 반 공기/1공기/곱빼기, 국물 토글, 개수 스테퍼, 반찬 1젓가락, '먹은 것만 체크', 150 kcal 미만 '간식' 라벨, 검색·최근 음식·직접 입력
8. 산식 1개(5장), 매시간 잠정, D+1 09:00 확정, 점수 장부(일별 분해·클램프·변경 이력)
9. 리더보드 오늘/누적, 포디움·내 행 고정·격차, 반영률 4칸 칩, 응원 하트 1일 1회(보내는 사람 기준 하루 1회, 수신자별 아님), 익명 신고, 검토 중은 타인에게 '집계 중'
10. 부정 방어 최소선 + 인앱 소명 1회(7장)
11. 푸시 7종(03 §8 N-01~N-07): 예약 3종 — 09:30 어제 확정 결과(N-01), 21:00 조건부 미확정·미동기화(N-02), 운영자 공지(N-03) / 트랜잭션 3종 — 분석 완료(N-04, §3-6), 검토 안내·소명 요청(N-05), 판정 결과(N-06, §4 OP3 당사자 푸시) / 건강 넛지(N-07, §7-8). 생명주기 전환 푸시는 없음(P5 상태 칩)
12. 운영자 웹 콘솔 4페이지, 다중 챌린지 데이터 모델(challenge_id 1급 키)
13. 사진: EXIF 제거·≤1,568px, 서버 SHA-256·시각, 종료+7일 후 원본 파기
14. 접근성: 다크모드 시스템 추종, 대비 4.5:1, 터치 44pt/48dp, 배지는 색+아이콘+텍스트

**보류(v1.1~v2)**: 팀전, 주간 탭, 운영자 순위 옵션·심박 존 리그, T 개인화(1회차 장부 병기 후), 기준선 주 7일(→ 첫 3일 점검으로 축소), 금전 정산·포인트·추첨, 체중 보조 리더보드, Play Integrity/App Attest(nullable 필드만 예약), Galaxy 기압계 층수, 케이던스 가변 MET, 바코드·OCR·음성, FoodLens A/B·평가셋 게이트, 배지·스트릭·피드·패스 카드, 알림톡·QR, pHash·워터마크, 벤더 API, 규칙 버전 재동의, 2인 확인·RBAC, 다국어.

## 5. 순위 산식 확정

**기호·기본값(챌린지 공통, 시작 후 잠금)**
- BMR_p: Mifflin-St Jeor(남 10W+6.25H−5A+5, 여 −161). 프로필은 시작 시 잠금, 변경은 운영자 문의. 비현실 값(BMI<15·>45) 재확인
- A_d: MET 엔진 순 활동 kcal, 상한 **C=1,000**(=2T)
- I_d: Σ 확정 끼니(150 kcal 이상) + Σ 확정 간식(150 kcal 미만) + 빈 주식 슬롯(아침/점심/저녁) × 대체값 **M_p=max(700, 0.45·BMR)**. 미확정 AI 초안은 확정 배치에서 **max(M_p, 1.3×AI)**로 자동 확정(수정 가능). '건너뜀'은 0(1일 1회·주 3회, 반복+상위 30% 플래그). 간식은 슬롯을 채우지 않고 대체값도 없지만 kcal은 I_d에 합산(끼니를 149 kcal 이하로 나눠 찍어 슬롯을 비우는 우회 차단)
- F_p=max(1,200, 0.8·BMR): 섭취 하한 클램프. 건강 넛지 임계(남 1,500/여 1,200)는 산식과 분리
- T=500 kcal/일 고정(T∝W 값은 장부에 병기만)

**산식**
D_d = (BMR_p + min(A_d, C)) − max(I_d, F_p),  S_d = 100 × clamp(D_d/T, 0, 1.5) → 0~150점
예외: 150 kcal 이상 확정 끼니 0개 → S_d=0. 누적=Σ S_d, 동점 공동 순위. 매시간 잠정, **D+1 09:00 KST 확정**, 이후 판정 변경은 '정정'. 순위 제외: 기록 모드·경고 3회·강퇴(타인에게 미노출).

**예시 1 — 폰만 사용자**: 70 kg 남, BMR 1,650, 걸음 9,000, 3끼 확정 1,800
- 걸음 계수 (3.8−1)×70/6,000=0.0327 kcal/보 → A=294
- F=max(1,200, 1,320)=1,320 → I=1,800
- D=1,650+294−1,800=144 → S=**28.8점**

**예시 2 — 워치 사용자**: 58 kg 여, BMR 1,290, 걸음 12,000(그중 4,500보는 워치 자동 기록 30분 달리기 세션, 9 km/h→MET 8.5), 3끼 확정 1,350, 워치 활동 칼로리 380은 참고값
- 세션 밖 걸음 7,500×(2.8×58/6,000=0.0271)=203, 세션 (8.5−1)×58×0.5=217.5 → A=420.5
- F=max(1,200, 1,032)=1,200 → I=1,350
- D=1,290+420.5−1,350=360.5 → S=**72.1점**(워치 칼로리와 무관, 같은 공식)

**검증 — 미기록**: 예시 1 인물이 1끼 600만 확정 → I=600+2×742.5=2,085(M_p=0.45×1,650=742.5, 화면 표시는 약 743) → D<0 → 0점(보고서 w_d 원안 62.4점 구멍 차단). 커피 100 kcal 사진은 간식: I에 합산(→2,185)되지만 슬롯 미충족이라 대체값은 그대로.

## 6. 칼로리 엔진 확정

**소비** E_d=BMR_p+A_d. A_d = 걸음 net + 세션 net + 층수 보너스.
- 걸음 net = (세션 창 밖 걸음, 일 30,000 상한)×(3.8−1)×W/6,000 — 2024 Compendium 17190 고정 MET(케이던스 버킷은 기기 입도 편향 때문에 v2)
- 세션 net = Σ(MET−1)×W×h, 자동 기록만(recordingMethod≠MANUAL_ENTRY, WasUserEntered=false). 달리기 MET 속도 tier <8 km/h 7.5 / 8~9.6 8.5 / 9.7~12.8 9.3 / ≥12.9 12.0, 계단 세션 6.8, 걷기 세션은 걸음과 동일. 세션 창 걸음은 시간 범위 집계로 제외
- 층수 = min(층, 50)×(6.8−1)×W×17.5/3,600 → 70 kg 약 2 kcal/층, 최대 ≈100 kcal. flightsClimbed/FloorsClimbedRecord 있을 때만, 없으면 카드 숨김
- 입력: HKStatisticsCollectionQuery / aggregateGroupByPeriod 1일 집계만, 원시 합산 금지, Asia/Seoul 자정, dataOrigin/HKSource 저장, 참가자×일 1행. 플랫폼 활동 칼로리는 참고 표시만

**섭취** I_d = Σ 확정 끼니 + Σ 확정 간식 + 대체값(5장).
- 인식: Gemini 2.5 Flash(Vertex AI, JSON 스키마: is_food, items[{name_candidates[3], count, portion_bucket, has_broth, confidence}]), Claude Haiku 4.5 스왑 어댑터
- kcal = 식약처 음식 표준데이터(15100070) 1인분 × 분량 배수 × 개수 × 국물 계수(0.6). 매핑 pg_trgm + 동의어 100개. 미매칭 → LLM 임시값+'확인 필요' 배지
- 저장: ai_kcal / confirmed_kcal / 수정폭 분리, 순위·링은 확정값만, 수정 로그는 v2 평가셋

## 7. 부정 방지·안전 규칙 확정

1. 순위에는 확정값만, AI 초안 별도 보존
2. 소비는 자동 기록만, 출처 기록·표시, 미확인 출처 플래그
3. 상한: 활동 1,000 kcal·걸음 30,000·층수 50·점수 150/일. 하한: F 클램프
4. 대체값 + 간식 규칙(슬롯 미충족·I_d 합산) + max(M, 1.3×AI) + 건너뜀 주 3회 → '안 찍기·큰 끼니 미확정·커피로 채우기·끼니 분할 촬영' 차단. '일부만 찍기'는 구조적으로 남음 → 규칙 화면에 한계 명시
5. 프로필 시작 시 잠금(+10 kg ≈ +28점/일 억제), 비현실 값 검토
6. 사진: 인앱 카메라 전용, 서버 시각, EXIF 제거, SHA-256 중복
